## 1. Crate and API

### TS-01 Crate layout and optional Bolt

- **Requires**: FR-API-003, NFR-REL-002, NFR-SAFE-001.
- **Options**: (a) one crate `lpg`, Bolt behind a Cargo feature; (b) a workspace of published crates (engine, bolt, algorithms).
- **Evidence**: redb, fjall, neo4rs each ship one crate (R-REDB, R-FJALL, R-NEO4RS). NFR-REL-002 names one published crate.
- **Decision**: (a). One crate `lpg` with `#![forbid(unsafe_code)]`; feature `bolt` (not default) gates the Bolt module. Internal modules: `api`, `session`, `tx` (MVCC, locks, validation), `storage` (io, page, buffer, btree, wal, checkpoint, recovery), `catalog`, `index`, `gql` (lexer, parser, binder, planner, exec), `types`, `proc`, `algo`, `ops` (backup, restore, import, export, migrate), `obs`, `bolt`. Algorithms are always compiled (no requirement makes them optional).

### TS-02 Public async API and threading

- **Requires**: NFR-PLAT-003, FR-API-001/008/009/010, FR-SES-004, FR-DB-008/009.
- **Options**: (a) async engine throughout; (b) synchronous engine core, async boundary at the API, blocking work off tokio workers; (c) a dedicated thread per open result.
- **Evidence**: tokio forbids blocking in async tasks and offers `spawn_blocking` (D-TOKIO). Page I/O is synchronous `pread`/`pwrite` (TS-08). Measured on this host (P3 Q4.2): `spawn_blocking` hand-off 13.9 µs per crossing; thread + channel 13.8 µs per item; batch of 1 024 rows 2.3× faster than row-at-a-time in a toy pipeline. Memgraph and Neo4j execute statements synchronously (R-MG `plan/operator.hpp:102-131`).
- **Rust crates**: none provides this boundary; tokio is used directly.
- **Decision**: (b).
  - Handles: `Database` (cheap `Clone`, `Arc` inside), `Session`, `Transaction`, `ResultStream`. `ResultStream::next().await` moves the cursor to `spawn_blocking`, fills one batch, returns it (no `futures`/`Stream` dependency, as neo4rs `RowStream::next`).
  - Background work (WAL writer, checkpointer, GC) runs on `std::thread`s owned by the handle. Dropping a handle stops them without a checkpoint (FR-DB-009).
  - A session holds an atomic "busy" flag; a second concurrent request fails (FR-SES-004).
  - Errors: one hand-written `Error` type carrying a GQLSTATUS code, message and cause (FR-BOLT-006); no `thiserror`.
  - Async hooks of application traits (ABS-001, ABS-002) return boxed futures (`Pin<Box<dyn Future + Send>>`) so the traits stay dyn-compatible (D-AFIT) without `async-trait`.

### TS-03 Storage abstraction (ABS-003)

- **Requires**: ABS-003, FR-STO-002, NFR-VER-004, FR-DB-006/007.
- **Evidence**: redb `pub trait StorageBackend` (`len`, `read`, `set_len`, `sync_data`, `write`, `close`; R-REDB `src/db.rs:74`); turso `pub trait IO` / `pub trait File` (R-TURSO `core/io/mod.rs:153,424`); SQLite crash-simulating VFS for power-loss tests (R-SQLITE `src/test6.c` header).
- **Decision**: a synchronous, dyn-compatible trait at file level: `open`, `create`, `remove`, `rename`, `list`, `sync_dir`, `try_lock`, and per file `read_at`, `write_at`, `sync_data`, `set_len`, `len`. The default implementation uses `std::fs` and `std::os::unix::fs::FileExt` (safe positional I/O). Backup, restore, export and migration files also pass through it (FR-STO-002 "every file operation").

- **Decision**: lpg implements its own page store, buffer pool, B+tree, WAL, checkpoint and recovery on `std`.

### TS-05 Files and page format

- **Requires**: FR-STO-001, FR-REC-003/008, FR-OPS-004.
- **Evidence**: page sizes PostgreSQL 8 KiB, Neo4j `PAGE_SIZE = 8192` (R-NEO `io/.../PageCache.java:51`), InnoDB 16 KiB, SQLite and Kuzu 4 KiB (R-KUZU `CMakeLists.txt:114`). PostgreSQL keeps `pg_control` ≤ 512 bytes for atomic writes (P1 Q9).
- **Decision**:
  - Layout: `<db>/LOCK` (TS-27), `<db>/CONTROL` (magic, format version, page size, database UUID, checkpoint redo LSN, next element id, CRC-32C; replaced by write-temp + `sync_data` + `rename` + `sync_dir`), `<db>/data` (one paged file; page 0 is a header with magic and format version), `<db>/wal/` (segments).
  - 8 KiB pages, fixed at creation. Page header: CRC-32C, page LSN, page type, tree id.
  - Slotted leaf and inner pages; values above an inline threshold go to overflow page chains (SQLite overflow pages).
  - Free pages: a persisted free-page list plus an in-memory set; a page freed by a transaction is reusable only after the GC horizon passes it.

### TS-06 Graph record layout  [P5-D1, D3]

- **Requires**: FR-STO-001/003, FR-TX-006, FR-TYPE-003, BR-TYPE-001, FR-CAT-001, NFR-SIMP-001.
- **Options**: (a) Neo4j record chains (fixed records addressed by id); (b) per-node adjacency blocks (Neo4j block format, LiveGraph); (c) columnar + CSR (Kuzu); (d) clustered B+trees.
- **Evidence**:
  - Neo4j records: node 15 B, relationship 34 B with prev/next pointers for both endpoints; ids are file offsets and are reused (R-NEO `record-storage-engine/.../NodeRecordFormat.java:32`, `RelationshipRecordFormat.java:31-35`; P2 L1.1). Neo4j's newer block format co-locates adjacency per node and uses a B+tree "sorted by relationship type and direction" for dense nodes (Operations Manual "Store formats", P2 L1.1).
  - Kuzu (columnar + CSR) allows one write transaction (R-KUZU `transaction/transaction_manager.cpp:35-38`).
  - Memgraph keeps adjacency in RAM (fails FR-STO-001).
  - Measured (P4, 1 M nodes / 10 M edges, Zipf 0.8, online inserts): 2-hop degree-weighted, all pages resident: fixed B+tree 7.9 ms, compressed B+tree 11.5 ms, node blocks 4.7 ms, record chains 79.6 ms. Cache at 25 %, misses from the device: 317 ms, 110 ms, 229 ms, 18.6 s. Space per edge: 159.2 B, 59.8 B, 128.9 B, 68.6 B.
- **Rust crates**: indradb 5.0.0 and cozo 0.7.6 store graphs as sorted key-value entries (MPL-2.0, 41 k and 115 k downloads): study only. No crate provides a disk graph layout usable here.
- **Decision**: (d). Per graph: a node tree (`node_id` → labels, properties), an edge tree (`edge_id` → src, dst, type, properties) and one clustered adjacency tree keyed `(node_id, direction, edge_type, neighbour_id, edge_id)` with two entries per edge, each carrying `created_ts` and `deleted_ts`. Fixed-width entries first; leaf prefix compression (P4 model B) is the first candidate optimisation, added only when the NFR-PERF-002 baseline shows a target missed (NFR-SIMP-001). Record chains rejected on measured I/O; node blocks rejected for a second allocator plus relocation plus a B+tree for dense nodes anyway.

### TS-07 Element identifiers

- **Requires**: FR-TYPE-003, BR-TYPE-001/002, FR-BOLT-001 (`element_id` from Bolt 5.0, D-SS).
- **Evidence**: PostgreSQL sequences log ahead (`SEQ_LOG_VALS 32`, R-PG `commands/sequence.c:58`). Neo4j reuses ids (spec S11).
- **Decision**: one 64-bit counter per database for nodes and edges, monotonic, never reused, kept below 2^63 so it also fits the Bolt legacy integer `id`. Each WAL commit frame records the counter's high-water mark; recovery takes the maximum. Bolt `element_id` is the decimal string of the counter value. Backup, restore and migration copy ids unchanged; import assigns new ones.

### TS-08 Buffer pool and memory cap  [P5-D4]

- **Requires**: FR-STO-001, FR-LIM-001/003, NFR-SAFE-001.
- **Evidence**: PostgreSQL clock sweep (R-PG `storage/buffer/README:175`); Neo4j usage-count sweep (R-NEO `MuninnPageCache.java:983-984`); DuckDB one `BufferPool` for cache and operators (P1 Q3); `memmap2::Mmap::map` is `unsafe fn` (P1 Q3); PostgreSQL uses buffered I/O unless the developer option `debug_io_direct` is set (R-PG `doc/src/sgml/config.sgml:12891-12906`).
- **Rust crates**: none provides a buffer pool usable under `forbid(unsafe_code)`; `parking_lot` (study, measure later) vs `std::sync`.
- **Decision**:
  - Frames are `Box<[u8]>` behind per-frame `std::sync::RwLock` latches; sharded page table; atomic pin and usage counts; clock-sweep eviction; buffered `pread`/`pwrite`; no mmap, no `O_DIRECT`.
  - One memory accountant (atomic byte budget) shared by frames, operator state, private write sets, the version store, read sets and algorithm projections. A failed reservation evicts clean frames; if it still fails, the statement fails (FR-LIM-001), including when the version store would exceed the cap [P5-D4].
  - Default cap: 100 % of `MemTotal` if `SwapTotal` > 0, else 90 %, read from `/proc/meminfo` (FR-LIM-003).

### TS-09 WAL, group commit and durability

- **Requires**: FR-TX-001/002, FR-REC-001/002/006/007/008.
- **Options**: (a) record-level (physiological) redo with full-page writes (PostgreSQL); (b) redo + undo (InnoDB ARIES style); (c) full page images (SQLite WAL); (d) no log, copy-on-write (redb, LMDB).
- **Evidence**: PostgreSQL WAL CRC-32C per record (R-PG `access/xlogrecord.h:49`), 16 MiB zero-filled segments (`wal_init_zero = true`, `xlog.c:134`); SQLite WAL frames with commit frames and checksums (R-SQLITE `src/wal.c` header); Neo4j appends to the log then applies to the store (R-NEO `kernel/.../InternalTransactionCommitProcess.java:77-80`) with a dedicated `LOG_WRITER` thread draining batches (`kernel/.../wal/TransactionLogQueue.java:111,220`); InnoDB dedicated `log_writer` and `log_flusher` threads (R-INNO `log/log0write.cc:108-122`); turso leader/waiter group commit (R-TURSO `core/mvcc/database/group_commit.rs`); Memgraph writes the WAL under `engine_lock_` so commits are ordered by timestamp (R-MG `storage/v2/inmemory/storage.cpp:1081-1100`).
- **Rust crates**: okaywal 0.3.1 (17 k downloads, last release 2023-11-26): study only; fjall journal: study only.
- **Decision**: (c), redo-only, NO-STEAL (uncommitted data never reaches shared pages; TS-11).
  - A **group** is one durable unit: the final image of each page dirtied by the group's commits (each page once), then one commit frame listing the group's commit timestamps and the element-id high-water mark. Frames carry CRC-32C and the segment salt; a group whose commit frame is missing or invalid is discarded at recovery (SQLite commit-frame rule).
  - Images are captured under the commit latch (TS-12), so a group image never contains a later commit's change.
  - One dedicated WAL thread writes and `sync_data`s each group; committers await a notification (Neo4j, InnoDB pattern; no tokio worker blocks on fsync).
  - Segments: 16 MiB, created by writing zeros (PostgreSQL). ENOSPC while creating a segment fails the writing transaction and leaves reads working (FR-REC-007); any other WAL or data write or sync failure makes the database unusable (FR-REC-006).
  - Known cost: WAL volume of one 8 KiB image per page per group. It is recorded for the NFR-PERF-002 baseline; option (a) is the fallback if a target fails.

### TS-10 Torn-page protection

- **Requires**: FR-REC-002, FR-REC-003.
- **Evidence**: PostgreSQL full-page writes on first change after a checkpoint (R-PG `xloginsert.c`, `needs_backup = (page_lsn <= RedoRecPtr)`); InnoDB doublewrite buffer (R-INNO `include/buf0dblwr.h`, `buf/buf0dblwr.cc` recovery); Kuzu shadow file applied at checkpoint (R-KUZU `storage/shadow_file.cpp:66-79,91-135`); SQLite WAL page images; redb/LMDB copy-on-write.
- **Decision**: inherent in TS-09. A data page is written in place only after its image is durable in the WAL, and a WAL segment is recycled only after the checkpoint that covers it has synced the data file. Recovery overwrites whole pages from images, so a torn data page is always rewritten. Page checksums detect any other torn page. No doublewrite file, no separate full-page-write rule.

### TS-11 Checkpoint

- **Requires**: FR-OBS-001 (checkpoint metrics), FR-REC-001/002, FR-DB-008.
- **Evidence**: PostgreSQL fixes the redo pointer, then flushes buffers dirty at that moment (P1 Q4); Neo4j defaults `db.checkpoint=PERIODIC`, 15 min, 100 000 transactions (D-CFG); Kuzu checkpoints after a WAL size threshold (R-KUZU `main/db_config.cpp`).
- **Decision**: PostgreSQL-style fuzzy checkpoint: record the redo LSN, flush every frame dirty at that LSN (WAL-before-data rule), `sync_data` the data file, replace `CONTROL`, recycle segments below the redo LSN. Triggers: Neo4j defaults (15 min or 100 000 transactions, whichever first), clean close, and backup start. In-memory statistics (TS-17) are persisted at each checkpoint.

### TS-12 Checksums, corruption and integrity check

- **Requires**: FR-REC-003/005/008/010.
- **Evidence**: CRC-32C in the PostgreSQL WAL, InnoDB pages (`innodb_checksum_algorithm=crc32`) and Neo4j log entries (R-NEO `wal/.../CommitLogEntrySerializerV4_2.java:67`); redb XXH3-128 (P1 Q6). Neo4j has a consistency checker module (R-NEO `community/consistency-check`).
- **Rust crates**: `crc32c` 0.6.8 (Apache-2.0/MIT, 85.9 M, no runtime dependencies; repository pushed 2026-02-09): **dependency**. `crc-fast` (depends on `spin`): fallback. `crc32fast` computes CRC-32/IEEE, not CRC-32C: rejected. `xxhash-rust` (BSL-1.0): rejected.
- **Decision**: CRC-32C on every page (verified on every read from disk), every WAL frame and `CONTROL`. A failure while open sets a database-wide "unusable" latch (FR-REC-005/006). Open verifies `CONTROL` and the WAL from the redo point (FR-REC-008). The on-demand integrity check (FR-REC-010) scans every page checksum, B+tree invariants and cross-tree consistency (adjacency ↔ edge tree, indexes ↔ data).

### TS-13 Recovery

- **Requires**: FR-REC-001/002/003/008, FR-DB-009.
- **Decision**: open = take `LOCK` → verify `CONTROL` and format version (TS-25) → scan WAL from the redo LSN → apply page images of complete groups in order → stop at the first invalid frame; an invalid frame followed by any valid frame is corruption and the open fails → restore the id counter from the highest commit frame → empty version store → checkpoint. No undo phase (NO-STEAL).

## 3. Transactions

### TS-14 MVCC  [P5-D4]

- **Requires**: FR-TX-001/003/004/006, FR-ALG-004, FR-LIM-003.
- **Evidence**: Memgraph applies writes in place with newest-to-oldest delta chains and GC from the oldest active start timestamp (R-MG `storage/v2/delta.hpp`, `inmemory/storage.cpp:3044,3115`; `--storage-gc-cycle-sec` 30, `flags/general.cpp:105`); Kuzu keeps uncommitted inserts in `LocalStorage` (P2 L1.1); Neo4j keeps transaction state in memory and applies it at commit (R-NEO `kernel/.../api/state/TxState.java`, `InternalTransactionCommitProcess.java`); HyPer and Wu et al. (P2 L2.1).
- **Rust crates**: turso `core/mvcc` (Hekaton/Larson MVCC, MIT): study only; surrealkv, fjall snapshots: study only. None can be a dependency without its storage (TS-04).
- **Decision** (P2 L2.3):
  - Private write set per transaction (records, adjacency, index and catalog entries), charged to the memory cap; reads merge it over the snapshot.
  - Immutable stamped entries (adjacency, indexes, catalog): visibility by `created_ts`/`deleted_ts`; an update is a delete-stamp plus an insert.
  - Mutable records (node and edge labels and properties): newest committed version in place with `version_ts`; older versions in an in-memory, non-durable before-image store, newest to oldest.
  - GC horizon = oldest active snapshot; GC runs after commits and on a 30 s cycle (Memgraph default); physical removal of dead entries is logged like any page change.
  - Snapshot = highest published commit timestamp (TS-16).

### TS-15 Serializable isolation and write locks  [P5-D5]

- **Requires**: FR-TX-003..008, BR-TX-001, FR-STO-003.
- **Options**: (a) PostgreSQL SSI (SIREAD locks, dangerous-structure detection); (b) HyPer-style commit-time validation of read predicates; (c) single writer (Kuzu, redb, LMDB); (d) strict 2PL.
- **Evidence**: PostgreSQL SSI, predicate locks at tuple/page/relation granularity (R-PG `storage/lmgr/README-SSI:300-322`), `predicate.c` 4 993 lines (P2 L3.1); HyPer validation against writes committed during the transaction, read-only transactions exempt (P2 L3.1); PostgreSQL REPEATABLE READ/SERIALIZABLE: a writer waits for a concurrent updater and fails if it commits ("could not serialize access due to concurrent update", R-PG `executor/nodeModifyTable.c:403`); Neo4j Forseti detects deadlocks while waiting (R-NEO `lock/.../ForsetiClient.java:836`); Memgraph has no serializable level and no lock waiting (R-MG `isolation_level.hpp:20`, `mvcc.hpp:170-212`). (c) fails FR-STO-003/FR-TX-005; (d) fails FR-TX-006.
- **Rust crates**: fjall `OptimisticTxDatabase` records single, range and full reads and rejects a commit that overlaps a later commit's writes (R-FJALL `src/tx/optimistic/conflict_manager.rs`, `oracle.rs`): the same family as (b), study only (TS-04). `txn`/`skipdb` (7 k downloads): too little use.
- **Decision**: (b) [P5-D5], with PostgreSQL's write-write rule.
  - Read set = list of `(tree, key range)`; validated at commit against keys written by commits in (snapshot, own commit_ts); ranges coarsen to whole trees over a memory budget. Read-only transactions and snapshot-isolation transactions skip validation.
  - Lock table keyed by `(graph, resource)` with X and S modes (P2 L4.2): node content X, node existence X (delete) / S (edge create/delete on endpoints), edge X, unique value `(constraint, value)` X. Locks are held to commit end.
  - A writer that obtains a lock on an element whose `version_ts` is newer than its snapshot fails with a serialisation failure (FR-TX-008).
  - Deadlock detection at request time: depth-first search of the waits-for graph; the requester that closes a cycle aborts (FR-TX-007). Waiters wake on cancellation.
  - Consequence: write-back algorithm runs and other large read-write transactions fail if any concurrent commit touched what they read (accepted in P5-D5).

### TS-16 Commit protocol

- **Requires**: FR-TX-002, FR-STO-003, FR-BOLT-017.
- **Decision**: validate (TS-15) → take the commit latch → draw `commit_ts` → apply the write set to pages, copying before-images first → join the open WAL group → release the latch → await group durability → publish `commit_ts` in timestamp order → release locks → return (with a Bolt bookmark). Transactions execute concurrently; only apply is serialised, as Memgraph serialises timestamping and WAL order under `engine_lock_` (R-MG `storage.cpp:1081`). A commit whose group fails to sync fails and makes the database unusable (FR-REC-006).

## 4. Catalog, indexes, constraints

### TS-17 Catalog and statistics  [P5-D9]

- **Requires**: FR-CAT-001..004, FR-DB-005, FR-AUTH-002, FR-PROC-004.
- **Evidence**: token maps in Neo4j (`token-api/.../TokenHolder.java`) and Memgraph (`name_id_mapper.hpp`); Neo4j and Kuzu keep count statistics, Neo4j histograms only for tests (P3 Q3.1).
- **Decision**: one catalog B+tree per database with stamped entries (TS-14), so DDL and DML mix and roll back together (FR-CAT-004): `(parent_id, name) → (object_id, kind, owner, definition)`, reverse entries, token tables for labels, edge types and property keys, index and constraint definitions. Directories are created through the Rust API, since GQL has no create-directory statement (P3 Q6.1) [P5-D9]. Statistics: node counts per label, edge counts per `(label, type, direction)`, index entry and distinct-key counts; in memory, updated at apply, persisted at checkpoint.

### TS-18 Indexes and constraints  [P5-D6]

- **Requires**: FR-IDX-001..005, FR-TYPE-005, FR-API-004.
- **Evidence**: Neo4j point index = Hilbert space-filling curve keys in its B+tree (R-NEO `spatial-index/.../curves/HilbertSpaceFillingCurve2D.java`, `...3D.java`; `PointIndexReader`); Memgraph point index = in-memory boost R-tree (R-MG `indices/point_index_expensive_header.hpp:18`); Memgraph index entries carry timestamps and are pruned by GC (R-MG `inmemory/label_property_index.hpp:62`); Neo4j online population queues concurrent updates (R-NEO `kernel/.../index/MultipleIndexPopulator.java`); Neo4j uniqueness via an `INDEX_ENTRY` lock (P2 L4.1).
- **Rust crates**: rstar 0.13.0 (in-memory R*-tree, not page-based): study only. fast_hilbert and hilbert_2d are 2D only (crates.io descriptions); 3D is required (SRID 4979, 9157): study only.
- **Decision**: every index is a B+tree of stamped entries with an order-preserving key encoding: label/type lookup `(token, element_id)`; single-property and range `(index, value, element_id)`; composite = concatenated values; point = per-CRS 2D/3D Hilbert key plus an exact distance post-filter (own implementation). Online build: catalog entry POPULATING → writers maintain it from that commit → builder scans a snapshot and inserts if absent, honouring writer tombstones → ONLINE in a normal transaction (P2 L5.2; needs a deterministic concurrency test, TS-30). Uniqueness and node key: X lock on `(constraint, value)` at write, re-checked at apply. Existence and property type: checked on the write set at commit. Constraint creation blocks writers of that label or type while it validates existing data [P5-D6]; FR-IDX-005 covers index builds only.

### TS-19 Parser

- **Options**: (a) ANTLR-generated parser from `GQL.g4`; (b) LR generator (lalrpop); (c) PEG (pest, peg); (d) combinators (chumsky, nom); (e) hand-written lexer, recursive descent, Pratt expressions.
- **Evidence**: Neo4j (`cypher/front-end/parser/v25/.../Cypher25Parser.g4`), Memgraph (`query/frontend/opencypher/grammar/Cypher.g4`) and Kuzu (`src/antlr4/Cypher.g4`) all use ANTLR 4. `GQL.g4`: 3 774 lines, left-recursive labelled `valueExpression` (R-GQL l.2137-2163), "more permissive than a GQL implementation would be" (README). Each grammar ambiguity is resolved explicitly and recorded in the technical specification. Syntax errors: one GQLSTATUS code with position and expected tokens (code unverified, OQ-005).

### TS-20 Binder, planner, execution, EXPLAIN/PROFILE  [P5-D10]

- **Requires**: FR-API-007..010, FR-CAT-003, FR-GQL-004, FR-LIM-001/002, FR-OBS-005/006, FR-BOLT-021.
- **Evidence**: P3 Q2–Q4, Q7: Memgraph symbol table and pull cursors, cancellation checked every 20th pull (R-MG `plan/operator.cpp:510-528`); Kuzu binder, DP join order up to 7 relationships, cost = sum of cardinalities; Neo4j IDP, `LocalMemoryTracker`, `PROFILE` columns; Kuzu materialises full results (fails FR-API-010).
- **Rust crates**: none (DataFusion-class engines are relational and push-based): study only.
- **Decision**:
  - Binder: one pass AST → typed IR; variables resolved to slots with kind, degree (singleton/group/conditional) and static or dynamic type; three-valued logic; per-feature gating raises "feature not supported" (FR-GQL-002).
  - Planner: rule rewrites (predicate, projection, limit pushdown; index seeks), exact DP over expansions up to 7 relationships then greedy, cost = sum of intermediate cardinalities; `Expand`, `Expand(Into)` as a point lookup on the adjacency key; `Repeat` operators per restrictor; NFA product-graph BFS for selectors. No plan cache until measured.
  - Execution: pull, batch-at-a-time (1 024 rows, columns of `Value`), one thread per statement through `spawn_blocking` per batch, no intra-query parallelism [P5-D10].
  - Limits and cancellation: one atomic status per transaction set by Rust API cancel, Bolt `RESET`, termination and a tokio timer (time limit, `tx_timeout`); checked per batch and every K iterations in long loops; row and byte limits counted at the result sink; operator memory reserved in chunks from the accountant.
  - EXPLAIN returns the plan with estimates; PROFILE wraps operators in decorators recording rows, batches, per-batch time, storage and buffer hits, peak memory.

### TS-21 Values and types

- **Requires**: FR-TYPE-001..007, FR-SES-003, FR-BOLT-005, BR-BOLT-001.
- **Evidence**: Memgraph compact `PropertyStore` (R-MG `storage/v2/property_store.cpp:63-118`); measured `Value` layouts (P3 Q5: 24 B enum with `Arc` slices); Neo4j geographic distance = haversine with radius 6 378 140 m, 3D = haversine at mean height combined with the height difference by Pythagoras, Cartesian = Euclidean (R-NEO `values/.../CRSCalculator.java:130-166`).
- **Rust crates**: **jiff** 0.2.37 (Unlicense OR MIT, 209.3 M): **dependency**; reads `/usr/share/zoneinfo` or `TZDIR` by default (D-JIFF), as FR-TYPE-007 requires. chrono-tz compiles the IANA data in (D-CTZ): rejected. time has no IANA zone names (D-TIME): rejected. geo 0.33.1: not used (two formulas; Neo4j constants must be matched exactly).
- **Decision**: a 24-byte `Value` enum (inline scalars and common temporals; `Arc` strings, bytes, lists, records, paths; boxed rare types). Temporal arithmetic, IANA zones and the OS clock through jiff; session zone UTC by default. Points: own `Point2D`/`Point3D` with SRIDs 7203, 9157, 4326, 4979 and the Neo4j distance formulas. Record encoding: sorted label tokens, then properties sorted by key token with compact headers and minimal-width integers (Memgraph scheme). The set of numeric types beyond `i64`/`f64` (wide and unsigned integers, `DECIMAL`, `FLOAT16/128/256`) and any crate for them wait for the ISO text (OQ-005).

### TS-22 Bolt and PackStream (feature `bolt`)

- **Requires**: FR-BOLT-001..021, ABS-001, NFR-VER-003/005.
- **Evidence**: Neo4j server: one module per version `protocol/v40`…`v61`, state machine `fsm/StateMachineImpl.java`, PackStream `packstream/io/PackstreamBuf.java`, chunk codec `ChunkFrameDecoder/Encoder` (R-NEO `community/bolt`; the source already contains `BoltProtocolV61` while D-BC lists 6.0 as latest); Memgraph server states `handshake`, `init`, `executing`, `error` (R-MG `communication/bolt/v1/states/`); handshake ranges and manifest v1 (D-HS); structures (D-SS).
- **Rust crates**: neo4rs 0.8.0 (MIT, 1.2 M): client only, and its handshake offers only Bolt 4.0–4.4 at release and at head 0.9.0-rc.10 (R-NEO4RS `lib/src/version.rs:16-30`): study only. bolt-proto/bolt-client (MIT, ~49 k, last release 2022-12-28): unmaintained, study only. boltr, meshdb-bolt (≤ 6.3 k): too little use. No crate can be a dependency.
- **Decision**: own implementation of both endpoints over any `tokio::io::AsyncRead + AsyncWrite + Unpin + Send` stream supplied by the application (ABS-001 is that bound; no socket code).
  - Handshake: version ranges and manifest v1; versions 5.0–5.4, 5.6–5.8, 6.0; 4.x and below refused.

  - Bookmarks: `<database UUID>:<commit_ts>`; a bookmark with another UUID is invalid (FR-BOLT-017).
  - ROUTE: single-instance table, `ttl` 300, application-supplied advertised address.

### TS-23 Authentication and authorisation (ABS-002)

- **Requires**: ABS-002, FR-AUTH-001/002, BR-AUTH-001, FR-BOLT-011..013, FR-OBS-003/004.
- **Evidence**: Neo4j privilege names (D-PRIV).
- **Decision**: one dyn-compatible trait with boxed-future methods: `authenticate(scheme, credentials) → principal [+ home schema/graph] | refusal`, `impersonate(principal, target) → principal | refusal`, `authorise(principal, action, object, owner) → allow | deny`. Actions follow Neo4j's names: data `TRAVERSE`, `READ`, `CREATE`, `DELETE`, `SET LABEL`, `REMOVE LABEL`, `SET PROPERTY`; catalog `CREATE`/`DROP` per object kind (directory, schema, graph type, graph); `CREATE/DROP/SHOW INDEX`, `CREATE/DROP/SHOW CONSTRAINT`; `SHOW TRANSACTION`, `TERMINATE TRANSACTION`. The object of a data action is its graph. Checks run once per statement, after planning and before execution, for every `(action, object)` the plan can perform; a statement whose plan could perform a refused action fails even if it would not have performed it.

### TS-24 Procedures, functions and metrics (ABS-004, ABS-005)

- **Requires**: ABS-004/005, FR-API-005/006, FR-PROC-001..004, FR-ALG-002, FR-OBS-001, FR-OPS-005/006, FR-OBS-002.
- **Evidence**: Neo4j procedure modes and run-time write restriction; Memgraph immutable graph for read procedures (P3 Q8.1); `metrics` crate recorders are process-global or thread-scoped (D-METRICS).
- **Rust crates**: tracing 0.1.44 (MIT, 893.2 M): **dependency** (FR-OPS-005). metrics 0.24.6: rejected, it has no per-handle sink. async-trait: not needed.
- **Decision**:
  - Procedures: per-handle registry of typed signatures (parameters, result columns, `ReadOnly`/`ReadWrite`); synchronous implementations returning row iterators, run on the statement thread with a context (snapshot, cancellation, memory tracker); read-only enforced by the context type, at plan time and by classifying nested GQL. Built-ins `show_transactions`, `show_indexes`, `show_constraints`, `show_catalog` and every algorithm are registered the same way. Memory allocated by a procedure without reserving it is outside the cap; rows it returns are accounted [P5-D11].
  - Metrics: own sink trait (`counter`, `gauge`, `histogram` with static names) per database handle, categories of FR-OBS-001.
  - `tracing` events per request carry the query text and `tx_metadata`, never parameter values.

## 7. Algorithms and operations

### TS-25 Graph algorithms

- **Requires**: FR-ALG-001..005, NFR-REL-004.
- **Evidence**: Neo4j GDS runs algorithms on in-memory compressed projections (D-GDS); graphalgs (inventory source A) builds on petgraph and nalgebra (R-GALGS `Cargo.toml`; `nalgebra` used in `spec/laplacian.rs`, `spec/st.rs`); petgraph `Csr` implements its visit traits (`IntoNeighbors`, `NodeIndexable`, `IntoEdges`…; R-PETGRAPH `crates/petgraph/src/csr.rs:551-811`).
- **Rust crates**: petgraph 0.8.3 (MIT OR Apache-2.0, 533.5 M; runtime deps fixedbitset, hashbrown, indexmap): **dependency**. nalgebra 0.35.0 (Apache-2.0, 92.7 M, MSRV 1.89): **dependency** for dense linear algebra (ALG-076 spectral clustering, ALG-143 Laplacian, ALG-151 spanning-tree count). rand 0.10.3: **dependency** (randomised algorithms, database UUID). rustworkx-core (pulls rayon, ndarray, priority-queue and others): study only. graphalgs (16.9 k): study only. faer: not used (nalgebra is used by the reference source).
- **Decision**: each run projects the caller's snapshot, filtered by labels and types, into a petgraph `Csr` by one ordered scan of the adjacency tree, charged to the memory cap. Entries sourced from petgraph call it; all others are implemented in lpg over petgraph's visit traits. Randomised algorithms take a `seed` parameter; when absent, a fixed default seed is used, so FR-ALG-002's equal-results criterion holds (deviation from GDS, where the seed is optional and runs are otherwise non-deterministic). Write-back mode writes properties in the caller's transaction.

### TS-26 Backup, restore, import, export

- **Requires**: FR-OPS-001..003/007..010, FR-IMP-001..005, BR-TYPE-002, FR-REC-004.
- **Evidence**: PostgreSQL base backup = checkpoint + file copy + WAL range, replayed at restore (P1 Q7); Neo4j full backup copies the store and recovers (P1 Q7); Neo4j import header format: types `int … vector`, arrays `type[]` with `;`, `:ID`, `:LABEL`, `:START_ID`, `:END_ID`, `:TYPE` (D-HDR); APOC JSON Lines and GraphML layouts (D-APOC); GraphML `attr.type` limited to six scalar types (D-GML).
- **Rust crates**: csv 1.4.0 (Unlicense/MIT), serde_json 1.0.151 (+ serde), quick-xml 0.42.0 (MIT): **dependencies**.
- **Decision**:
  - Backup (physical): take `start` = redo LSN of the last completed checkpoint and pin WAL recycling; copy `CONTROL` and every data page through ABS-003; flush the WAL, record `stop`, copy WAL `[start, stop]`; unpin. Every page written during the copy was modified after `start`, so its image is in the copied WAL.
  - Restore: into an empty location only (FR-OPS-009), then recovery to `stop`; element ids preserved.
  - CSV follows the Neo4j header format; JSON Lines follows APOC's node/relationship objects; GraphML follows APOC's layout; the native dump is an lpg binary format (versioned, CRC-32C, the TS-21 value encoding). Encoding of types these formats cannot carry: [Q2](#q2).
  - Fast initial load: B+trees built bottom-up from sorted input into unreferenced pages, data synced, then one WAL group installs the roots; the target graph must be empty (FR-IMP-002).

### TS-27 Single-process exclusion

- **Requires**: FR-DB-006/007, NG-4, FR-STO-002.
- **Evidence**: `File::try_lock` stabilised in Rust 1.89.0, implemented with `flock(LOCK_EX|LOCK_NB)` on Linux; measured: a second descriptor in the same process gets `WouldBlock`, another process is refused (P1 Q8, `locktest/main.rs`); fjall locks its database the same way (R-FJALL `src/locked_file.rs`).
- **Rust crates**: fs2 (last release 2018), fs4, fd-lock: not needed since std 1.89.
- **Decision**: `<db>/LOCK` locked with `File::try_lock` through `Storage::try_lock`, covering both other processes and a second open in the same process.

### TS-28 Format versioning and migration

- **Requires**: FR-OPS-004/011..013, BR-TYPE-002.
- **Evidence**: Neo4j migrates only stopped databases and rewrites all data (spec S8, S9); no downgrade (S10).
- **Decision**: one `u32` format version in `CONTROL` and the data header. Open fails with "migration required" on N−1 or older and fails without writing on a newer version. Migration N−1 → N runs on a closed database: it writes the new files in a temporary directory inside the database location, syncs them, then switches by replacing `CONTROL` (rename + `sync_dir`) and removes the old files; a crash before the switch leaves the old database intact. Element ids are copied unchanged.

### Q2

**Conflict: FR-IMP-001 acceptance vs the formats' type systems.** FR-IMP-001 requires that a graph exported and imported in each of CSV, JSON Lines and GraphML keeps the same property values. GraphML allows only six scalar `attr.type` values (D-GML). APOC, the reference layout, writes temporal and spatial values as strings (D-APOC), so their type is lost. JSON has no temporal, point or byte-string type. The Neo4j CSV header covers temporal and point types but not byte strings, `DECIMAL`, wide or unsigned integers, records or nested lists (D-HDR).

- a) **(Recommended)** Keep the acceptance; add an lpg type annotation where the format allows it (GraphML: string-typed keys with an lpg-namespaced type attribute; JSON Lines: a tagged object for non-JSON types; CSV: Neo4j header types plus lpg type names for the rest). Trade-off: lossless round trip in lpg; other tools see strings for those values.
- b) Follow APOC and Neo4j exactly, and limit the round-trip acceptance to types each format represents natively; the native dump stays lossless. Trade-off: no extensions; FR-IMP-001's acceptance must be amended.
- c) Refuse to export a value the format cannot represent, with an error naming it. Trade-off: no silent loss and no extensions; some graphs cannot be exported in some formats.
